# LLM-Wiki에서 가져온 프로젝트 기록 원칙

- 확인일: 2026-10-24
- 읽은 자료: [GeekNews의 LLM-Wiki 소개](https://news.hada.io/topic?id=28208)
- 소개 글이 연결한 원문: [Karpathy의 Gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
- 접근 범위: GeekNews 본문을 읽음. Gist는 시간 초과와 HTTP 502로 본문을 확보하지 못했으므로 원문을 직접 확인했다고 주장하지 않음.

소개 글은 원자료, 계속 갱신하는 위키, 에이전트 작업 규칙을 구분하고 인덱스·누적 기록·교차 참조를 유지하는 방식을 설명합니다. RouteLens에는 이 구조를 작게 적용합니다. 원문 전체를 복제하거나 별도의 검색 서버를 도입하지 않습니다.

## 적용 결정

- 기존 `docs/`가 설계의 기준입니다. 위키는 현재 구현 상태와 출처·시험 결과를 연결합니다.
- `wiki/index.md`에서 필요한 문서를 찾고, `wiki/log.md`에 변경·검증·남은 일을 누적합니다.
- 원자료 스냅샷은 덮어쓰지 않습니다. 출처가 바뀌면 날짜를 붙인 새 근거와 기존 판단의 수정 이유를 남깁니다.
- 원자료를 공개 저장소에 보관할 권리가 없다면 URL과 필요한 자체 요약만 기록합니다. 비공개 대화·실제 위치기록은 올리지 않습니다.
- 요약을 다시 요약한 내용은 새로운 검증으로 세지 않습니다. 코드·테스트·공식 출처까지 되짚을 수 있게 합니다.

이 방식이 실제 유지관리 부담을 줄이는지는 앞으로 관찰할 사항입니다. 글에 소개된 효용을 이 프로젝트에서 측정한 효과로 표현하지 않습니다.
