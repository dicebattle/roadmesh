# Governance

The initial maintainer is the repository owner. Proposals and implementation changes are reviewed in public; private location data and security-sensitive details are excluded from public discussion.

The project publishes its protocols, implementation, deployment instructions, compatibility tests and evaluation methodology. A hosted service may charge for operations and support. Self-hosting and interoperability must remain possible without a mandatory hosted account.

Protocol changes document compatibility, migration and failure behavior. Breaking changes require a new major version after the first stable protocol release. Before that release, every draft clearly states its compatibility limits.

Approving a routing node does not endorse its operator indefinitely. Admission, suspension, key revocation and reinstatement must have documented criteria and an audit trail without publishing private traffic.

When a second active maintainer joins, establish independent review for protocol and trust-root changes and a two-person release-key recovery procedure before opening the network to unrestricted participation. Until then, this project has a single-maintainer continuity risk.

Code is licensed under Apache-2.0. Map and traffic datasets require their own explicit licensing and privacy review. No participant grants permission to publish raw location history merely by contributing code or running a node.
