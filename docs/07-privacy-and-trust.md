# 위치정보 보호와 위협 모델

## 믿는 주체와 공개하는 자료

첫 시험에서는 동의한 운전자가 운영자 관리 수집 서버에 짧은 GPS 기록을 보냅니다. 원시 GPS를 받는 서버와 도로 매칭 서버는 운영자의 신뢰 영역 안에 둡니다. 자원봉사자에게 원시 기록을 넘겨 지도 매칭을 맡기지 않습니다.

경로 계산 노드는 요청의 출발지·목적지와 경유 정보를 볼 수 있습니다. 중계 서버는 사용자 IP와 요청을 볼 수 있습니다. 중계 방식은 임의 노드에 사용자 IP를 직접 노출하는 것을 줄이지만 종단간 익명성을 제공하지 않습니다. 승인된 노드 운영자의 보관 금지 약속만으로 이를 기술적으로 보증할 수 없으므로 참가 동의와 운영자 선택 화면에 이 경계를 설명합니다.

P2P에는 공개 승인을 거친 지도·교통정보 묶음만 게시합니다. IPFS의 전송 암호화는 게시 내용이나 참여 메타데이터의 비공개성을 보증하지 않습니다. 원시 GPS는 암호화했더라도 공개 P2P에 게시하지 않습니다. [IPFS 개인정보 문서](https://docs.ipfs.tech/concepts/privacy-and-encryption/)

## 초기 보관 정책 제안

| 데이터 | 위치 | 보관 제안 | 공개 여부 |
| --- | --- | --- | --- |
| 처리 전 GPS 배치 | 비공개 큐 | 최대 24시간, 처리 후 삭제 | 금지 |
| 매칭 문맥 | 운영자 매칭 서비스 | 세션 비활성 후 10분, 절대 최대 1시간 | 금지 |
| 실패 입력 | 자동 저장 금지 | 기본은 수·오류 분류만 저장 | 금지 |
| 중복 처리 키 | 집계 저장소 | 24시간, 원본 좌표 없이 저장 | 금지 |
| 기여자별 통과 관측 | 집계 저장소 | 창 마감 후 지연 허용·재시도 처리에 필요한 최소 기간, 최대 24시간 | 금지 |
| 공개 교통정보 | 객체 저장소 | 운영 보관 7일 후 삭제 | 조건 충족분만 |
| 시간대별 요약 | DB/객체 저장소 | 초기 30일, 필요성 재평가 | 별도 공개 판단 |
| 동의·접근 관리 기록 | 제한된 내부 DB | 실제 정책 검토 후 확정 | 금지 |

운영 로그·분산 추적·오류 수집·실패 큐에도 같은 정책을 적용합니다. 원본을 포함하는 실패 큐를 두는 경우 기본 보관값에 맡기지 않고 전체 24시간 한도를 보장해야 합니다. 보장이 어렵다면 원본 없는 오류 기록으로 대체합니다. 백업과 서비스 제공자의 보관 조건도 함께 확인합니다.

이 값들은 기술 설계 제안이며 법적 보관 의무에 대한 판단이 아닙니다. 실제 사용자 위치정보 수집 전에는 관할 법령과 서비스 형태에 맞는 동의·신고·삭제 요구를 별도 검토합니다. 합성 자료의 로컬 기술 검증과 실제 사용자 수집은 다른 단계입니다.

## 무엇을 방어해야 하는가

| 위험 | 초기 방어 | 남는 한계 |
| --- | --- | --- |
| 한 사람이 반복 업로드 | 기여자·구간·시간창 제한, 결정적 중복 키 | 여러 계정은 별도 문제 |
| 여러 가짜 사용자 생성 | 초대 기반 시험, 발급 한도, 이상 패턴 점검 | 누구나 참여하는 망의 진짜 운전자 수 증명 아님 |
| 조작 GPS·잘못된 도로 매칭 | 정확도·진행방향·통과시간 검사, 불확실 매칭 제외 | 서명된 GPS도 사실이라는 보장 없음 |
| 정체 지우기 | 신호대기·정체를 포함한 통과시간 사용 | 통과를 완료하지 못한 심한 정체는 관측 지연 발생 |
| 악성 경로 서버 | 승인 운영자, 응답 제한·버전 검사·표본 대조·폐기 | 최적 경로를 암호학적으로 증명하지 않음 |
| 오래된 교통정보 재생 | 순번·관측 창·만료·시계 오차 검사 | 심각한 시계 오차 때 실시간 기능 보류 필요 |
| 지도·프로그램 변조 | TUF, 해시·크기·키 검증, 안전한 파일 압축 해제 | 승인자가 잘못된 지도를 승인하는 문제는 별도 |
| 집·직장·반복 경로 추정 | 원본 비공개, 짧은 보관, 표본 기준, 기여 선택권 | 소수 표본 기준만으로 익명성 보장 불가 |
| 버스 데이터 편향 | `BUS` 분리, 전용차로·정류장 처리 | 승용차 대표성은 별도 검증 필요 |
| CPU·메모리 고갈 | 요청 길이·거리·시간 제한, 대기열 상한, 프로세스 격리 | 자원봉사 노드는 가용성 보장이 약함 |

추가적인 개인 보호를 위해 출발·도착 부근 관측 억제, 사용자 지정 비수집 구역, 공간·시간 범위 확대를 시험합니다. 다만 일부 점을 제외하는 것만으로 원래 경로가 복원되지 않는다고 주장하지 않습니다. 저표본 구간과 반복적인 스냅샷 차이를 이용한 추론도 검토합니다.

## 키와 노드 운영

지도 배포용 신뢰 루트는 일반 서비스 실행 키와 분리합니다. 지도 업데이트는 TUF의 역할·만료·키 교체 절차를 재사용합니다. 빠르게 바뀌는 교통정보는 별도 온라인 게시 키로 서명하고, 허용 지역·정책·만료 범위를 제한합니다. 그 키가 유출되면 신규 게시를 중지하고 키를 폐기하며 live 적용을 해제합니다.

서명 키는 Git·컨테이너 이미지·휴대폰에 넣지 않습니다. 로컬 시험 키는 합성 자료 전용이며 운영에서 거부되도록 식별합니다. 공개 운영 전에 다른 유지관리자와 복구 훈련을 합니다.

## 공개 전에 반드시 보여줄 증거

원시 좌표가 로그·공개 API·P2P·저장소에 나오지 않는 검사, 삭제 작업 재실행 후 잔여 데이터 조회, 변조/만료 자료 거부, 키 폐기 후 적용 중단, 기여 거부·철회 후 앱 동작을 확인합니다. 문서의 정책만 작성한 상태를 보호 기능 구현으로 표시하지 않습니다.
